## EarthSciIntegrator v0.2.0

This release moves EarthSciIntegrator to EarthSciAST 0.14.0 and
EarthSciASTDiff 0.6.2. Integration and adjoint behavior are unchanged, and
there are no other changes since v0.1.0. The public API and the run
configuration format may still change in any 0.x release.

### Breaking changes

- **Upstream versions.** This release requires these versions:
  - EarthSciAST 0.14 (esm 2.3.0); in Rust, `earthsci-ast` 0.14.0;
  - EarthSciASTDiff 0.6.2 or later;
  - EarthSciIO 0.4 (unchanged).

  EarthSciAST 0.13.0 and 0.14.0 are both breaking releases. esm 2.3.0 applies
  the pointwise lift on every route, deprecates `neg` and `pow`, and spells
  units and numbers canonically. EarthSciAST 0.14.0 also removes the plain-text
  expression surface. See EarthSciAST's release notes for how to migrate a
  model.
- **Rust: `earthsci-ast` types in the public API.** The planner exposes
  `earthsci_ast` types (for example, `model::node` returns
  `&earthsci_ast::ExpressionNode`). Code that passes these types across the
  API must use `earthsci-ast` 0.14.
- **Plan hashes change for some models.** EarthSciAST 0.14.0's flatten adds
  `output_idx` to an operator's pointwise-lifted `makearray`. The planner
  copies the flattened right-hand sides into its right-hand-side documents, so
  for a model that merges such an operator, those documents gain the key. This
  changes their `sha256` in `plan.json`. Jacobian documents, band values and
  all other plan fields stay the same. Rerun the planner to update any stored
  plan.

### Fixes from upstream

- Rust's native compiler now builds an unshaped `ifelse` whose array branch
  reads a calendar-template scalar (EarthSciAST#739). Reseact's NEI emissions
  need this.
- Julia's flatten is now linear on shared templates (EarthSciAST#737). Deep
  template chains no longer take exponential time.
