## EarthSciIntegrator v0.1.0

This release is the planner milestone (M2). The planner and both runtimes now
run on esm 2.x models through the current EarthSciAST, EarthSciASTDiff and
EarthSciIO releases. The planner now completes on the full reseact model in
both Julia and Rust, and the plans and derived documents the two languages
write are compared byte for byte against the checked-in goldens. The public
API and the run configuration format may still change in any 0.x release.

### Breaking changes

- **Upstream versions.** This release requires esm 2.x models and these
  versions:
  - EarthSciAST 0.12 (esm 2.1.0);
  - EarthSciASTDiff 0.6.1 or later;
  - EarthSciIO 0.4.

  esm 2.0.0 removes the built-in function, table and geometry operators, so an
  esm 1.x document that uses them is refused at load. Migrate it with
  EarthSciAST's codemod (`python -m earthsci_ast.migrate`). For example, `fn interp.linear`
  becomes the `linear` template of `esm:std/interp.esm`, and a two-record
  `update.from.records_per_sample` becomes `"records": true` on the record
  index set. Derived documents and plan hashes change for these models.
- **EarthSciIO 0.4 refuses uncovered run windows.** A run window that the data
  does not cover is refused with `esm_window_uncovered`. It is no longer
  served from the nearest record.
- **New plan-time refusals** (run-config rule 16). Before, these settings were
  planned and then failed only when the run was built:
  - `unsupported_time_derivative`: a Rosenbrock method, whether named or
    chosen for `"auto"`, on an operator that depends on time. Planned operators
    do not supply the time derivative yet.
  - `unsupported_dt_scope`: `dt_scope: "cell"`, which arrives with M3. The
    default `dt_scope` is now `"global"` (D94).
- **Julia dependencies.** DiffEqCallbacks and SciMLBase are now regular
  dependencies. A plan whose starting values read data works without loading
  them first.

### New

- **Bounded `solve` nodes (D95).** If a solve's unknown has an `lb` or `ub`
  bound on its model variable, the solve becomes a complementarity problem.
  `ptc`, `newton` and `picard` all project onto the bounds. The tape records
  the active set, and the adjoint handles the bounds.
  - The planner refuses a bound with the wrong sign (`solve_bounds_sign`) or an
    invalid bound (`solve_bounds_invalid`).
  - A state with lower bound 0 and no upper bound joins its leaf's
    `domain.nonnegative`.
  - Other bounds on states are refused (`unsupported_state_bounds`).
- **Validation that scales to full-size models (pass 8, D91).**
  - Julia's band check colours the Jacobian's columns as Rust's already did.
    On reseact chemistry this takes 2 evaluations per sampled state instead of
    10,647.
  - Neither planner builds the whole model any more.
- **Kinks in the band check (D93).** When the central difference at the full
  step fails, the planner retries the central, forward and backward
  differences at one tenth and one hundredth of the step. The report says
  which one accepted each entry.
- **Accurate versions in `plan.report.json`.** The Rust planner now reports
  the EarthSciAST and EarthSciASTDiff versions it was built with, not fixed
  strings.

### Fixes

- Rust band entries no longer carry EarthSciAST's internal template-origin
  marker, so a band read from the probe document equals the same band read from
  the written terms.
